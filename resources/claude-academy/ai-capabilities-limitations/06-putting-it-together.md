# Lessons 12–13: Putting it together and next steps

## Lesson 12 — When Properties Collide (3 min video)

- The four properties do not work alone. **Most real failures are two properties meeting.**
  Name which two, and you know which fix to use.
- Interactive: drag two property nodes together to see the failure mode and the targeted fix.
  Short labels from the page:
  - Next Token Prediction: generates what *sounds* right
  - Knowledge: knows what it was trained on
  - Working Memory: attends to what is nearby
  - Steerability: follows the loudest instruction
- Diagnostic pairs the lesson names:

| Pair | Failure |
| --- | --- |
| Next Token Prediction + Knowledge | Hallucinated specifics (e.g. fake citations) |
| Working Memory + Steerability | Long-conversation drift |

- Other failure patterns in the lesson goals: confidently wrong math, agreeable bad premises
  (sycophancy).
- Fixes to reach for: verify specifics, re-supply context, offload to code execution, invite
  pushback.
- **4D connection:** this diagnosis is **Discernment** applied. You judge better when you know
  what kind of wrong you are looking at.

**Exercise: The failure diagnosis**
1. Recall 2–3 times AI output disappointed or surprised you. Write a sentence or two on each:
   what you asked, what you got, what was wrong.
2. Tell the AI each story and ask which of the four properties were likely at play and why.
3. Check its diagnosis against what you now know. Push back if you disagree (watch for the
   sycophancy fingerprint from Lesson 3).
4. Ask for the most targeted fix for each diagnosis, and test it on a similar task if you can.
5. Review your annotated task list (property tags, verification scores, knowledge flags,
   context needs, goal statements). For the hardest tasks, write which two properties collided.

**Reflect:**
- Did naming the pair change the fix you would choose? Would you have tried a weaker fix before?
- Which property pair will you meet most in your daily work?

## Lesson 13 — Next Steps (5 min video)

- Fluent AI use is not about memorizing every failure. It is holding a **small, clear model of
  the machine** so you can tell which kind of wrong you see and respond.
- You now have: four properties as continuums, and typical failures as property intersections.
- This framework and the 4D Framework are **two sides of one system**: the properties explain
  what the 4D competencies respond to.
- **Calibrated trust:** locate your task on each continuum, then match your verification and
  context habits to that spot.
- Models keep changing. The *shape* of the properties stays useful even as the exact lines move.

**Exercise: Your commitment**
1. Revisit the Lesson 1 task list. For each task, note where it lands on each property's
   continuum and what mitigations you might need.
2. Choose one task and one change for this week (a verification step, standing-context setup,
   a checkpoint, or stating the goal and not only the format). Write it down.

**Reflect:**
- What is the biggest change in how you think about AI behavior since Lesson 1?
- Which of the 4Ds did this course sharpen most for you?

(see my notes in `../ai-fluency/`). Keep testing the edges as models improve.
